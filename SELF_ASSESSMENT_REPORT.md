## What we did not manage

- In `src/db.js`, the `idempotency_keys` table enforces the 24-hour retention window at read time (`WHERE created_at >= datetime('now', '-24 hours')`) rather than running a periodic background purge (`DELETE FROM idempotency_keys WHERE created_at < datetime('now', '-24 hours')`). For an in-memory SQLite slice reset on restart, read-time filtering is sufficient, whereas a persistent production database in `PA#3`+ will need scheduled expired-key cleanup.
- In `main` branch protection, `required_approving_review_count` is set to `0` (while `required_pull_request_reviews`, `strict` status checks `gates` and `e2e` with `app_id: 15368`, and `enforce_admins: true` are all enabled) so PR merges are gated strictly by the automated CI checks without blocking on manual cross-account review click-throughs during milestone packaging.

## What we would do differently

- We would keep `AGENTS.md` under 30 lines from the very first draft and immediately wire `src/config.js` into `src/server.js` at the same time we write the rule *"never read `process.env` outside `src/config.js`"*, rather than letting the assistant write a rule that `src/server.js` did not yet follow.
- We would run Playwright `e2e` in CI on the first commit: CI Run [`42586953474`](https://github.com/danhuupham/leetkob/actions/runs/42586953474) caught a Node `22.13.0` `node:sqlite` V8 garbage-collection bug (`ERR_INVALID_STATE: statement has been finalized`) that in-process tests in `test/helpers.js` masked because `publishedAt()` held a reference to `db`.
